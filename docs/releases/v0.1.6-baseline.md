# v0.1.6 Compatibility Baseline

## Baseline Identity

v0.1.6 starts from `main` commit `89844ebd1d15bc2f60e08d08c653980b2bb6ef24` (`feat(v0.1.5): deliver sustainable long-term-use release candidate (#5)`, 2026-08-21). The repository version is `0.1.5`; v0.1.6 version changes are Phase-6 release work, not implementation evidence.

The baseline is schema `005_sustainable_use.sql` and the current 118-command generated IPC/capability surface. Its automated v0.1.5 evidence records 26 frontend test files / 158 tests and 495 Rust tests; remeasure these counts in Phase 0 rather than treating old counts as v0.1.6 evidence.

## Frozen Financial and History Contracts

- `Money`, `SignedMoney`, `Quantity`, `UnitPrice`, `FxRate`, return values, UUID identities, UTC timestamps, History Origin local dates, checked decimal arithmetic, and Money-boundary rounding retain their current contracts.
- Instrument and FX quotes are append-only. Selection remains `quoted_at DESC`, `created_at DESC`, then ID descending, filtered by the source preference effective at the selected time.
- Manual and Provider are the only existing quote preference kinds. Manual remains the default and fully offline path.
- Missing data never becomes zero, one, a cross-rate, or an estimate. Direct/inverse FX against Household base remains the only FX routing.
- Current valuation uses Rust `ValuationSnapshot`; historical valuation selects only quotes with `quoted_at <= cutoff`; snapshots are revised only through the existing dirty/rebuild path.
- Ledger, Activity legs, projections, History Origin, current state, lots, cost-basis declarations, gain, return, attribution, Benchmarks, freshness policies, Backup/Restore, import/export, and search retain their v0.1.5 contracts.

## Frozen Provider Preparation Surface

- `instruments` already holds nullable paired `provider_key` and `provider_symbol`, unique per Household when present; those remain provider metadata rather than financial IDs.
- `instrument_quotes` and `fx_quotes` already retain `source_kind`, `source_key`, delayed state, timestamp, and append order. Migration 006 must preserve every existing row and source key.
- Existing `refresh_instrument`, `refresh_required_fx`, `refresh_all`, and `search_provider_instruments` IPC entries, fake adapters, timeout handling, four-request legacy bound, and partial-result DTOs are preparation infrastructure. Production state currently initializes unconfigured adapters.
- The frontend has no HTTP plugin; capability and CSP tests forbid broad network/filesystem/opener/shell/clipboard surfaces. Native Rust networking must not loosen them.

## Frozen Data and File Boundaries

- Migration SQL owns physical schema and must be schema-only. No migration, initializer, bootstrap, ordinary read, or provider setup may contact a network or create a quote/Activity/snapshot.
- Backup remains the full-fidelity database round trip. Canonical export and manual CSV formats remain controlled interchange surfaces, not restore inputs or provider-cache exports.
- Every ordinary command acquires the shared operation permit. Restore and Delete All Data retain exclusive runtime boundaries. Provider work is ordinary shared work and must not outlive a terminal transition.
- No Tauri dev/build, migration smoke, history rebuild, backup, restore, or packaging operation may use the only real user database.

## Required v0.1.6 Compatibility Proof

- Schema-005 database and sanitized fixture migrate to schema 006 with all pre-existing facts, IDs, relationships, selected quote values, snapshot revisions, and analytics goldens unchanged before new provider data is added.
- Existing manual quote append/import, manual selection, direct/inverse FX, stale/fresh labels, Provider-unconfigured behavior in the baseline fixture, and partial refresh behavior remain covered.
- A provider quote appended before a historical cutoff is eligible under the existing selection rule; one after it is not. A provider cache row is never itself a valuation input.
- Backup/Restore retains provider quote/cache rows once added; canonical export, manual quote CSV import/export, and user financial facts do not silently acquire provider-cache semantics.
- Unsupported future schema `007` performs zero application writes and zero provider requests through all old and new command paths.
- Version synchronization, generated bindings, capability/CSP audits, formatting, Clippy, frontend tests, Rust tests, query/performance checks, and documentation link checks are rerun and recorded at closeout.
