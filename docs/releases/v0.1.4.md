# v0.1.4 Release Contract

## Purpose and Status

**Release theme:** Analytics and Performance — know why wealth changed.

**Development status:** Complete.

**Release status:** Release candidate. Feature implementation, generated bindings, locales, automated tests, and version synchronization to `0.1.4` are in the repository. Isolated-data launch, keyboard/VoiceOver smoke testing, arm64 `.app`/`.dmg` packaging, and the chosen signing/notarization policy remain named macOS release checks. This closeout does not mark the product Released and does not create a git tag or GitHub release.

v0.1.4 interprets the immutable ledger that v0.1.3 delivered. It separates contribution, market movement, currency movement, income, and fees instead of inferring performance from the difference between a starting and ending value. It adds no new financial fact to the ledger: every result is derived from posted Activities, the History Origin baseline, effective-dated state, recorded quotes, and daily snapshots.

The detailed implementation contract is split between this release scope, the [technical design](v0.1.4-technical-design.md), the [implementation plan](v0.1.4-implementation-plan.md), and the [compatibility baseline](v0.1.4-baseline.md).

## Release Goal

A Household can see what a position cost, what it is worth, how much of the change came from the market versus the currency, how much came from contributions rather than performance, and what portion of history Nestworth cannot explain.

The central invariant is:

> Nestworth reports a performance number only when every input it requires is present. It never fills a missing cost, quote, or snapshot with an estimate.

The supporting invariant carried forward from v0.1.3 is:

> A position whose acquisition history is unknown stays unknown until the user declares it.

## User Stories

- As an investor, I can see what each position cost and what it is worth now.
- As an investor, I can see realized gain when I sell, matched against specific acquisition lots.
- As a multi-currency investor, I can see how much of my gain came from the instrument and how much came from the exchange rate.
- As a user, I can see how much of my net-worth change was saving and how much was performance.
- As a user, I can see time-weighted return that ignores the timing of my contributions and money-weighted return that includes it.
- As a user, I can see investment income and fees as their own totals rather than buried in a balance.
- As an existing user with positions that predate Nestworth, I can declare what they cost, or leave them unknown and still get an honest partial answer.
- As a user, I can tell exactly why a performance number is unavailable and what to do about it.
- As an offline user, I can produce every v0.1.4 result without a market-data provider.

## Included

### Cost Basis and Lots

- FIFO tax lots derived from the posted Activity ledger. Lots are computed, not entered.
- A Buy opens a lot whose cost is the persisted gross settlement amount.
- A Sell consumes open lots in acquisition order and records each consumption.
- A position Transfer moves lots between Accounts, preserving cost, acquisition time, and basis status.
- History Origin baseline quantity, Opening Adjustment quantity, and Position Adjustment increases open unknown-basis lots.
- A Position Adjustment decrease consumes lots but produces an unexplained disposal rather than a realized gain.
- Explicit, append-only cost-basis declarations that supply a cost for one unknown-basis lot without creating an Activity.
- Lot inspection showing quantity, cost, acquisition time, basis status, current value, and unrealized gain.

### Gain

- Realized gain per disposal, per Instrument, per Account, per Household, and per period.
- Unrealized gain for every open lot with a known basis and an available quote.
- Gross gain excluding fees and net gain after allocated acquisition and disposal fees, reported as separate numbers.
- Investment income totals separated by income kind, attributed to an Instrument when the Activity records one.
- Investment fee totals separated by fee kind, including trade fees that carry no fee kind.
- Explicit unknown-basis quantity, unknown-basis value, and incomplete-input diagnostics on every aggregate.

### Currency Decomposition

- Base-currency gain split into instrument movement and currency movement for every lot whose acquisition FX quote is available.
- The decomposition is an exact identity, not an approximation.
- A missing acquisition FX quote marks only the affected lot as undecomposed and its parent aggregates as incomplete.

### Return

- Daily-linked time-weighted return over a selected period.
- Money-weighted return as XIRR over the same period and scope.
- Household, Portfolio, Account, and Instrument scopes with scope-relative flow definitions.
- Cumulative return always, annualized return only for periods of at least 365 days.
- Explicit unavailability with named blocking dates when a required daily snapshot is missing or incomplete.

### Net-Worth Attribution

- A bridge from net worth at the start of a period to net worth at the end.
- Named components for external contributions, external withdrawals, investment market movement, currency movement, income, fees, debt principal movement, and cross-currency conversion spread.
- An explicit unexplained residual that makes the bridge balance exactly without hiding anything.
- Remeasurement of monetary components reported as unexplained return; remeasurement of Quantity reported as unknown-basis flow.

### Product Experience

- A top-level `/analytics` route with URL-backed scope and period state.
- Return, gain, income, fee, and attribution presentation with accessible tabular alternatives for every chart.
- A lot table with basis status and a declare-basis action.
- An unknown-basis worklist listing every position that blocks a complete answer.
- Unrealized gain and basis status on the Investments page and Account detail.
- English and Simplified Chinese copy for all workflows, method names, availability states, errors, and empty states.

## Excluded

v0.1.4 does not implement:

- Benchmarks, index series, peer comparison, or relative return
- Average-cost, specific-lot identification, LIFO, HIFO, or any lot policy other than FIFO
- Tax reporting, wash-sale rules, tax-lot optimization, or jurisdiction-specific cost rules
- Any change to posted Activities, legs, snapshots, or current state
- Fabricated lots, inferred acquisition dates, or cost derived from the first available quote
- Short positions, negative cash, margin, options, derivatives, or leveraged-position modeling
- Corporate actions including splits, mergers, spin-offs, and symbol changes
- Risk metrics such as volatility, drawdown, beta, or Sharpe ratio
- Forecasting, projection, target allocation, or planning
- A live quote or FX vendor
- Recurring or pending Activities, CSV import and export, backup and restore, or sync
- Background analytics computation while Nestworth is closed

## Locked Product Decisions

| Decision | v0.1.4 contract |
| --- | --- |
| Lot policy | FIFO only; no configuration, no user lot selection |
| Lot storage | Derived by deterministic replay of the posted ledger; lots are not a persisted financial fact |
| Reversed Activities | An Activity and its Reversal are both excluded from the lot replay; the audit records remain visible |
| Correction | The replacement Activity participates in the replay; the reversed original does not |
| Cost source | The persisted gross settlement amount only; recomputed unit price is never treated as an execution fact |
| Fees and basis | Fees are never capitalized into cost; gross and net gain are separate outputs |
| Unknown basis | Origin, Opening Adjustment, and Position Adjustment quantities are unknown-basis until explicitly declared |
| Declaration shape | Append-only, immutable, keyed to an origin item or Activity leg, revoked by appending a revocation |
| Declaration effect | Supplies cost only; never changes Quantity, Account Value, net worth, a snapshot, or the Activity ledger |
| Quantity remeasurement | Position Adjustment decrease is an unexplained disposal, never a realized gain |
| Currency decomposition | Exact identity `base gain = instrument movement + currency movement` using historical acquisition FX |
| Missing acquisition FX | Affected lot is undecomposed; parent aggregates are incomplete; no estimate is substituted |
| TWR method | Daily-linked geometric chaining over closed-day snapshots |
| MWR method | XIRR with actual/365 day count, solved in decimal arithmetic |
| Incomplete snapshot | Blocks return for any period containing it; the blocking dates are named |
| Annualization | Only for periods of at least 365 days |
| Attribution residual | An explicit unexplained bucket; the bridge is never forced to balance by adjusting a named component |
| Signed values | Gain and return introduce new signed output types; `Money`, `Quantity`, `UnitPrice`, and `FxRate` stay unsigned |
| Floating point | Still prohibited everywhere, including return solving; decimal mathematics only |
| Financial authority | Rust services only; frontend renders DTOs and chart geometry |
| Provider dependency | None; all analytics remain manually operable offline |
| Write surface | Cost-basis declaration and revocation are the only new writes in v0.1.4 |

## Gain and Return Definitions

| Term | Definition |
| --- | --- |
| Lot cost | Gross settlement amount of the acquisition, in the Instrument quote currency |
| Realized gain (gross) | Disposal proceeds minus consumed lot cost, excluding all fees |
| Realized gain (net) | Gross realized gain minus the disposal fee and the pro-rata acquisition fee of the consumed lots |
| Unrealized gain (gross) | Current market value of open lots minus their cost, excluding fees |
| Unexplained disposal | Value removed by a Position Adjustment decrease; excluded from realized gain |
| Instrument movement | Base-currency gain attributable to price change, measured at the acquisition FX rate |
| Currency movement | Base-currency gain attributable to FX change, measured on the ending native value |
| Investment income | Income Activities whose endpoint is inside the scope, by income kind |
| Investment fee | Fee-role legs inside the scope, by fee kind where recorded |
| Scope flow | A value movement that crosses the boundary of the analyzed scope |
| Time-weighted return | Geometric chain of daily returns with each day's scope flow removed |
| Money-weighted return | The rate that makes the net present value of scope flows and endpoint values zero |
| Basis complete | Every open and consumed lot in the aggregate has a known cost |
| Input complete | Every quote and snapshot required by the aggregate is present |

Instrument movement and currency movement satisfy an exact identity for each lot:

```text
base cost      = native cost  × acquisition FX
base value     = native value × ending FX
base gain      = base value − base cost
instrument     = (native value − native cost) × acquisition FX
currency       = native value × (ending FX − acquisition FX)
base gain      = instrument + currency
```

## Acceptance Scenarios

### FIFO Realized Gain

QQQ is quoted in USD. Three trades post in this order:

```text
Buy   2 QQQ × 100 USD  gross 200 USD  fee 5 USD
Buy   4 QQQ × 120 USD  gross 480 USD  fee 6 USD
Sell  4 QQQ × 150 USD  gross 600 USD  fee 6 USD
```

FIFO consumes the whole first lot and half of the second:

```text
Consumed cost       = 200 + (480 × 2/4) = 440 USD
Proceeds            = 600 USD
Realized gain gross = 160 USD
Allocated fees      = 5 + (6 × 2/4) + 6 = 14 USD
Realized gain net   = 146 USD
Open lot remaining  = 2 QQQ at cost 240 USD
```

At a `160 USD` quote the open lot is worth `320 USD`, so unrealized gross gain is `80 USD`. No Activity, Account Value, Holding Quantity, or snapshot changes when these numbers are produced.

### Currency Decomposition

A lot of `2 QQQ` cost `200 USD` when the market rate was `1 USD = 6.5 CNY`. It is now quoted at `150 USD` per unit with `1 USD = 6.9 CNY`, and the Household base is CNY:

```text
Base cost           = 200 × 6.5 = 1300 CNY
Base value          = 300 × 6.9 = 2070 CNY
Base gain           = 770 CNY
Instrument movement = (300 − 200) × 6.5 = 650 CNY
Currency movement   = 300 × (6.9 − 6.5) = 120 CNY
```

The two components sum to the base gain exactly. If no FX quote exists at or before the acquisition time, this lot reports base gain only, its decomposition status is `unavailable`, and every aggregate containing it is marked incomplete.

### Unknown Basis

A migrated Household holds `3 QQQ` captured by the History Origin baseline. At a `700 USD` quote and `1 USD = 6.9 CNY` the position is worth `14490 CNY`.

```text
Unrealized gain        = not reported
Unknown-basis quantity = 3
Unknown-basis value    = 14490 CNY
basisComplete          = false
```

After the user declares a total cost of `1500 USD`, the same position reports an unrealized gross gain of `600 USD` and `basisComplete` becomes true. The declaration creates no Activity, does not change the `3` Quantity, does not change net worth, and does not invalidate any snapshot.

### Time-Weighted Versus Simple Change

```text
Day 0 close   net worth = 100000
Day 1         deposit   =  10000
Day 1 close   net worth = 112200
Day 2 close   net worth = 114444
```

Flows are treated as available for the whole day they occur on, so the day's contribution counts in the denominator:

```text
Day 1 return = (112200 − 100000 − 10000) / (100000 + 10000) = 2%
Day 2 return = (114444 − 112200) / 112200                    = 2%
TWR          = 1.02 × 1.02 − 1                                = 4.04%
```

A naive `(114444 − 100000 − 10000) / 100000 = 4.444%` is not reported anywhere. If the Day 1 snapshot is missing or incomplete, no return is reported for any period containing Day 1 and the response names Day 1 as the blocking date.

### Net-Worth Attribution Bridge

```text
Net worth at T0            = 100000 CNY
External contributions     = +10000
Investment market movement =  +5900
Currency movement          =  +1800
Income                     =   +500
Fees                       =   −200
Debt principal movement    =      0
Conversion spread          =   −100
Unexplained                =   +100
Net worth at T1            = 118000 CNY
```

The components sum to the observed change exactly because `Unexplained` absorbs the residual. `Unexplained` is always displayed, never redistributed into a named component, and never suppressed when it is zero.

### Reversed Trade

A Buy of `2 QQQ` at `100 USD` is later reversed. The Activity list still shows the original and the reversal with their correction badges. The lot ledger contains neither of them, so no realized gain is ever matched against a lot the user has declared did not happen. If a correction replaced that Buy with `2 QQQ` at `110 USD`, only the replacement opens a lot.

## Release Acceptance

v0.1.4 is complete only when:

- Migration `004` preserves every v0.1.1, v0.1.2, and v0.1.3 identity, observation, Activity, leg, snapshot revision, correction link, and current total.
- Migration `004` creates zero cost-basis declarations and zero Activities.
- Unsupported future databases receive zero application writes from every analytics command.
- Every v0.1.3 golden value in the [compatibility baseline](v0.1.4-baseline.md) is unchanged.
- The FIFO replay is deterministic, produces the same lots for the same ledger on every run, and never depends on current projection state.
- An Activity and its Reversal are both absent from the lot replay while remaining visible in the ledger.
- Lot cost comes from the persisted gross settlement amount and never from a recomputed unit price.
- A Sell that exceeds known-basis quantity consumes unknown-basis lots and marks the result incomplete rather than assuming zero cost.
- Realized gain, unrealized gain, gross gain, and net gain are separately reported and internally consistent.
- Fees never appear inside a cost basis and never disappear from the fee totals.
- A Position Adjustment decrease produces an unexplained disposal and never a realized gain.
- A position Transfer preserves lot cost, acquisition time, and basis status, and produces zero gain.
- Currency decomposition reproduces the base gain exactly for every lot with an available acquisition FX quote.
- A missing acquisition FX quote, market quote, or snapshot marks only its own aggregate path incomplete and never substitutes zero, one, or an estimate.
- Cost-basis declarations are append-only, immutable, revocable only by a new record, and produce no ledger, state, net-worth, or snapshot change.
- A declaration for a lot identity that does not exist is rejected and writes nothing.
- Daily-linked TWR reproduces the acceptance scenario exactly and refuses to report a period containing an incomplete or missing snapshot.
- XIRR converges within its documented bounds or reports `unavailable`; it never returns an unconverged value.
- Annualized return is withheld for periods shorter than 365 days.
- The attribution bridge balances exactly with an explicit unexplained residual for every period whose endpoint snapshots are complete.
- Household, Portfolio, Account, and Instrument scopes use one return engine and one flow-classification rule.
- No persisted or reported financial value uses `f32`, `f64`, SQLite `REAL`, or JavaScript `number`, including return rates.
- Frontend code performs no cost-basis, gain, return, attribution, FX, or allocation calculation.
- Analytics reads add no N+1 query over lots, Activities, snapshot days, or snapshot items.
- English and Simplified Chinese locale keys, generated IPC bindings, frozen command allowlist, CSP, logging, and error shielding are current.
- Cost, gain, return, lot, and declaration values never appear in logs.
- Domain, migration, replay, gain, decomposition, return, attribution, command, frontend, golden, and compatibility tests pass through `bun run check`.
- Isolated-data launch, keyboard navigation, VoiceOver smoke testing, arm64 packaging, and the chosen distribution policy remain named macOS release checks. They are not claimed complete in this closeout.

## Compatibility Promises

v0.1.4 preserves every v0.1.1, v0.1.2, and v0.1.3 promise and adds:

- Analytics are read-only over the ledger. The only new write is a cost-basis declaration, which carries no financial state.
- Cost-basis declaration identities remain stable and reference an origin item or Activity leg that already exists.
- A declaration never becomes an Activity, and a later release must not convert one into fabricated trade history.
- Lot identity is derived and may be recomputed differently by a future release; the ledger facts it is derived from may not be reinterpreted.
- Realized gain reported for a past period may legitimately change when a correction is posted, because a corrected Activity is economically nonexistent. The audit chain that explains the change stays visible.
- Gain, return, and attribution outputs are presentation results, never inputs to valuation, net worth, or the Activity ledger.
- The eight-value wealth-flow classification is unchanged; scope-relative flow is an additional derived view, not a replacement.
- v0.1.5 may add lot policies, benchmarks, or imported basis, but must not silently reinterpret an existing FIFO result or an existing declaration.
