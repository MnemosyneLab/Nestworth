# v0.1.5 Compatibility Baseline

This document freezes the implemented v0.1.4 surface that v0.1.5 must preserve. It is Phase 0 evidence, not a product-decision forum. Executable truth remains the current migrations, code, fixtures, tests, generated bindings, and capability allowlist.

The repository is already versioned `0.1.5` as a development line, but the implemented feature baseline is v0.1.4. None of the planned v0.1.5 entities or commands exists merely because the manifests use the next development version.

## Frozen Runtime and File Boundaries

- `AppState` owns one `SqlitePool` and a shared/exclusive operation gate. Restore and destructive reset enter a terminal restart-required state before closing the pool; later commands return `APP_RESTART_REQUIRED` without touching SQLite.
- `writable_db()` returns the pool for `Writable` state and maps blocked bootstrap status otherwise.
- `delete_all_data` clones and closes the pool, removes pre-migration snapshots, WAL/SHM, and the live database, then relies on restart/onboarding behavior.
- Rust owns verified Backup/Restore bundles, JSON/CSV file contents, archive parsing, checksums, staging, atomic replacement, and recovery-file inventory. The frontend receives only typed DTOs and selected-file summaries.
- Media file selection uses `dialog:allow-open`; Rust reads the selected path. The frontend has no filesystem plugin.
- Database paths, media source paths, and driver errors are shielded from ordinary frontend errors and sensitive logs.

Restore therefore requires an explicit shared/exclusive runtime operation gate and terminal restart state. It must not treat a closed pool as a sufficient state machine.

## Frozen Activity and Analytics Boundaries

### Ledger

- Posted Activity input rejects future effective time.
- Activity header plus typed additive legs is immutable.
- Reversal and correction append linked evidence.
- ActivityService is the only post-origin financial mutation path.
- Activity preview writes nothing and create revalidates inside `BEGIN IMMEDIATE`.
- Cross-currency Transfer derives transaction FX from exact native amounts and reports conversion spread separately.
- Current classification remains the closed eight-value set; callers cannot provide it.

### History

- History Origin timezone is confirmed and immutable before the first Activity or snapshot.
- Closed-day snapshots are append-only revisions.
- Rebuild is explicit, local, provider-free, and bounded to 366 days.
- Missing valuation inputs remain explicit and are never zero-filled.

### Analytics

- FIFO lots are derived in memory from the ledger and are not persisted.
- `cost_basis_declarations` are the only v0.1.4 financial-adjacent writes; they never create Activities or change value.
- A declaration is keyed to an origin Holding or acquisition Activity leg and is revoked by appending a revocation.
- Origin and Adjustment quantities remain unknown-basis until declared.
- TWR is daily-linked; XIRR is money-weighted. Their definitions cannot change for Benchmark comparison.
- Gain, return, and attribution are Rust-computed and remain unavailable when required inputs are missing.

v0.1.5 import must not turn a declaration into a Buy, manufacture an acquisition time, or silently change a FIFO replay result.

## Frozen Decimal and Time Contract

| Type | Scale/sign |
| --- | --- |
| Money | Unsigned, up to 12 integer and 4 fractional digits |
| Quantity | Unsigned, up to 18 integer and 8 fractional digits |
| UnitPrice | Unsigned, up to 12 integer and 8 fractional digits |
| FxRate | Positive, up to 8 integer and 12 fractional digits |
| SignedMoney | Signed analytics output, Money boundary rounding |
| ReturnRate | Signed decimal fraction, 6 fractional digits at DTO boundary |

`rust_decimal` with checked operations remains mandatory. No financial value uses `f32`, `f64`, SQLite `REAL`, or JavaScript `number`.

Authoritative timestamps are UTC RFC 3339 milliseconds with `Z`. Activity schedule and Benchmark calendar dates use the confirmed History Origin IANA timezone. Existing latest-selection tie-breaks remain timestamp/date, creation time, then typed ID.

## Frozen Application Architecture

- Application “services” are modules of free functions; there are no service structs.
- Public application entry points take `&AppState`; transaction-scoped helpers use `_in_tx` and `&mut Transaction`.
- Shared transaction helpers live in `application::reference`.
- Tauri commands are thin functions in `ipc.rs` and `commands/`.
- Frontend calls only generated commands and never raw `invoke` names.
- Financial computation, schedule generation, duplicate classification, and Benchmark return belong in Rust.
- Current routes are lazy loaded; the app has no chart library and uses hand-rolled SVG geometry.
- Cursor pagination is manual and URL-driven rather than `useInfiniteQuery`.
- English and Simplified Chinese use one `common` namespace with parity tests.

v0.1.5 follows these patterns. A Rust application module may own file orchestration, but file parsing, validation, and database mutation remain separated enough to test without a native dialog.

## Query and Performance Freeze

Existing current reads retain their v0.1.4 bounded query behavior:

- Overview: no N+1 per Account
- Portfolio: no N+1 per Account or Holding
- Account detail: no N+1 per Holding or cash row
- Activity/timeline: keyset pagination and batched legs/references
- Analytics: batch ledger, declarations, snapshots, items, quotes, and FX rather than per-lot or per-day queries

- Pending list batches references and posted links.

- Import preview batches all referenced IDs before row-domain replay.

## Dependency Freeze

The current Rust manifest has no ZIP, SHA-256, or CSV crate and the frontend has no search/palette dependency. Phase 0 selects the following narrow additions for the consuming phases:

- ZIP: `zip` `8.6.0`, with default features disabled and Stored entries only; use entry-level streaming plus an application-owned allowlist and size/checksum validation. Do not enable AES, Deflate, BZIP2, Zstandard, time, or native compression features.
- SHA-256: RustCrypto `sha2` `0.11.0` with default features disabled; use SHA-256 only.
- CSV: `csv` `1.4.0` with default features disabled; use the streaming reader/writer and explicit row-size limits.
- No full-text database, fuzzy-search, cron, notification, filesystem-plugin, backup-service, or cloud SDK
- No frontend command-palette dependency unless Phase 0 evidence proves the existing primitives cannot meet accessibility requirements

Phase 0 reviewed the selected maintained crate licenses and MSRV against the current Rust toolchain (`rustc 1.97.1`). Adding them remains deferred to the phases that consume them; each addition must record feature resolution, binary-size impact, transitive capabilities, advisories, and duplicate-native-library results.

The exact recurrence, fingerprint, Backup, Benchmark, and search vectors are frozen in `src-tauri/test-fixtures/v0.1.5-goldens.md`.
Review references: [zip-rs/zip2](https://github.com/zip-rs/zip2), [RustCrypto sha2](https://github.com/RustCrypto/hashes/tree/master/sha2), and [BurntSushi rust-csv](https://github.com/BurntSushi/rust-csv). Their selected licenses are MIT, MIT OR Apache-2.0, and Unlicense/MIT respectively.

## Compatibility Test Obligations

- Released v0.1.1, v0.1.2, v0.1.3, and the Phase 0 sanitized schema-4 fixture migrate to schema `005` without changing existing facts or goldens.
- Migration SQL alone creates schema and zero v0.1.5 business rows.
- Post-migration policy initialization creates exactly four defaults once and no financial row.
- Reopen is idempotent.
- Unsupported future migration `006` remains byte-for-byte unchanged and receives zero writes from every command.
- Backup/Restore round-trip preserves every table, BLOB, ID, timestamp, decimal string, archive reference, correction chain, snapshot revision, and declaration.
- JSON export is deterministic for the same consistent database state.
- Import cannot bypass origin, archive, future-time, Money, Activity, quote, or declaration contracts.
- `foreign_key_check`, `integrity_check`, generated-binding drift, locale parity, log redaction, capability allowlist, and documentation links remain release gates.
