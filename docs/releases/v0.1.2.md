# v0.1.2 Release Contract

## Release Goal

**Theme:** Know what everything is worth.

v0.1.2 extends the v0.1.1 Household balance sheet into a multi-currency portfolio. A user must be able to retain native amounts, value cash and investment positions in the Household base currency, understand which quotes were used, and keep working when every network provider is unavailable.

This document owns product scope and acceptance for v0.1.2. The implementation is defined in the [technical design](v0.1.2-technical-design.md), and delivery order is defined in the [implementation plan](v0.1.2-implementation-plan.md).

**Development status:** Complete.

**Release status:** Release candidate. Feature implementation, generated bindings, locales, and automated tests are in the repository. arm64 packaging, signing, notarization, isolated-data launch, and VoiceOver remain named macOS release checks.

**Approval state:** The local data and valuation contracts are implemented. The external market-data provider decision in [Preparation Gate](#preparation-gate) is closed for this release: no live vendor is configured.

## Baseline

v0.1.2 starts from the completed v0.1.1 implementation and preserves its Household, Member, Institution, Group, Account, Ownership, Account Value, MediaAsset, archive, database-compatibility, and IPC contracts.

The current baseline has these relevant limits:

- Every current Account and Account Value uses the Household base currency.
- `Holdings` can be parsed from persisted data but cannot be selected for a new Account.
- Every new Account requires an initial Balance or Manual Value observation.
- Overview reads the latest Account Value and has no quote or valuation diagnostics.
- No Instrument, Holding, cash-by-currency, instrument-quote, FX-quote, or provider table exists.
- Core startup and all manual v0.1.1 workflows have no network dependency.

## User Stories

- As a Household member, I can create a non-investment Account in a currency different from the Household base currency and supply the FX rate needed to value it.
- As an investor, I can create a Holdings-tracked Investment Account without inventing an initial Account Value.
- As an investor, I can create or reuse an Instrument and record a non-negative quantity in an Investment Account.
- As an investor, I can maintain multiple cash currencies within one Holdings-tracked Account.
- As a user, I can enter manual instrument prices and FX rates even when no provider supports the asset or currency.
- As a user, I can see the native amount, base-currency value, quote source, quote time, and freshness of a valued position.
- As a user, I can refresh only Instrument and FX pairs explicitly selected for Provider when provider capability is available; Manual pairs are never sent to a provider.
- As an investor, I can see complete legacy Balance and Manual Value investment Accounts in the Portfolio total, while incomplete accounts remain visible and are reported rather than treated as zero.
- As a user, I can understand that portfolio allocations include explicit manual/unclassified buckets for investment Accounts without Instrument identity.
- As a user, I can continue opening, browsing, and editing local data when a provider is slow, rate-limited, misconfigured, or offline.

## Included

### Multi-Currency Accounts

- Preserve one immutable Household base currency.
- Allow an Account default currency to differ from the Household base currency.
- Convert Balance and Manual Value Accounts through an explicit FX quote.
- Retain and display both native and base-currency amounts.

### Portfolio Model

- Instruments with type, market metadata, native quote currency, and optional provider identity.
- Holdings-tracked Investment Accounts.
- Current Holding quantities and optional notes.
- Multiple current cash balances by currency in one Holdings Account.
- Archive and restore for Instruments and Holdings, with retained-reference behavior.

### Quotes and Valuation

- Append-only manual and provider Instrument Quotes.
- Append-only manual and provider FX Quotes.
- Explicit quote-source preference for each Instrument and required FX pair.
- Deterministic quote selection, direct or inverse base-currency FX conversion, and checked decimal arithmetic.
- One Rust ValuationService used by Overview, Accounts, and Investments.
- Full checked Decimal precision through aggregation; four-place midpoint-nearest-even rounding only at Money DTO boundaries.
- Fresh, Delayed, Stale, Manual, and Unavailable presentation states.
- Deduplicated batch refresh of Provider-selected Instruments and FX pairs with partial-success reporting; Manual selections are skipped.

### Product Experience

- Holdings Account creation and detail editing.
- Instrument management and manual quote entry.
- Manual FX management for currency pairs needed by active data.
- Investments page with portfolio total, positions, account totals, and allocation by currency, country, and Instrument type.
- Clear loading, empty, partial, stale, unavailable, and provider-error states in English and Simplified Chinese.

## Excluded

v0.1.2 does not implement:

- Buy, Sell, Transfer, Deposit, Withdrawal, Dividend, Interest, Fee, or other Activity records
- Quantity history, trade reconstruction, or automatic Holding changes from Activities
- Cost basis, tax lots, realized or unrealized gain, income, fees, TWR, XIRR, benchmarks, or performance attribution
- Historical portfolio charts or daily Household valuation snapshots
- Multi-hop FX triangulation or inferred cross rates
- Short positions, negative cash, margin, options, derivatives, or leveraged position modeling
- Automatic bank, broker, wallet, or custody synchronization
- Background refresh, scheduled refresh, or refresh while the application is closed
- User-managed backup, import, export, cloud sync, or permanent deletion
- Changing the Household base currency or converting an existing Account between TrackingModes

The Investments page reports current value, not return. A manual quantity edit is current state and must not be presented as a trade.

## Locked Product Decisions

| Decision | v0.1.2 contract |
| --- | --- |
| Household base currency | Remains immutable after onboarding |
| Existing v0.1.1 Accounts | Retain their mode, currency, and Account Value history without reinterpretation |
| New Holdings Accounts | Investment category only; no initial Account Value |
| TrackingMode conversion | Not exposed |
| Missing required quote | Exclude the affected value and mark the aggregate incomplete; never substitute zero or one |
| Stale quote | Continue using the last selected quote and show its stale state |
| Provider failure | Preserve local data and last successful quotes; never block startup |
| Financial authority | Rust ValuationService only; frontend formats returned results |
| FX routing | Direct or inverse against the Household base currency only; no multi-hop graph |
| Network boundary | Rust provider adapters only; no frontend HTTP capability |
| Portfolio inclusion | Sum every complete, active, non-liability included Account, including legacy Balance and Manual Value investment Accounts; report incomplete Accounts and exclude their missing values |
| Allocation coverage | Use the same complete-account denominator as the Portfolio total and expose explicit manual/unclassified buckets for non-Holdings investment Accounts |
| Decimal boundary | Retain checked Decimal precision through aggregation; round only Money DTO values to four fractional digits with midpoint-nearest-even |

## Acceptance Scenario

The mandatory golden Household uses CNY as its base currency and contains a Holdings Account with:

| Position | Native value input |
| --- | --- |
| SGD cash | `5000 SGD` |
| QQQ | `3 × 700 USD` |
| ES3 | `1000 × 4 SGD` |

With `1 USD = 6.9 CNY` and `1 SGD = 5.3 CNY`, the backend must produce:

```text
SGD cash   = 26,500 CNY
QQQ        = 14,490 CNY
ES3        = 21,200 CNY
Account    = 62,190 CNY
```

The same account must produce identical totals whether a selected quote was entered manually or returned by a provider with the same decimal value. Each component retains its native amount and quote provenance.

## Release Acceptance

v0.1.2 is complete only when:

- A committed sanitized v0.1.1 fixture contains representative Household/settings, Members/Ownership, Institutions/Groups, Balance and Manual Value investment Accounts, liabilities, Account Value history, archives, and retained references; migration preserves every row and relationship and preserves the pre-migration Overview result before v0.1.2 data is added.
- Re-running startup after migration is idempotent, and the pre-migration snapshot and unsupported-future-database zero-write contracts still pass.
- Existing Balance and Manual Value Accounts work unchanged, including when they are included investment Accounts.
- New foreign-currency Balance and Manual Value Accounts use the selected FX quote and expose native and base values.
- Holdings Accounts support Instrument reuse, current quantities, multiple cash currencies, and manual price and FX fallback.
- Quote selection and freshness are deterministic, and checked decimal operations return safe domain errors on invalid or overflowing input.
- Full-precision component values are aggregated before Money DTO rounding; account, portfolio, and Overview totals do not sum rounded components.
- Missing quotes make affected totals explicitly incomplete and identify every excluded item.
- Batch refresh requests only Provider-selected Instruments and normalized FX pairs at most once, persists successful results, skips Manual pairs, and reports partial failures without rolling back unrelated successes.
- Overview, Account detail, and Investments agree because they use the same valuation path and consistent database snapshots.
- Archived Instruments and Holdings are omitted by default while retained references remain resolvable.
- All new commands use generated bindings, all UI strings exist in English and Simplified Chinese, and frontend code performs no authoritative financial arithmetic.
- Domain, migration, repository, transaction, command, frontend, golden, provider-fixture, precision, and compatibility tests pass.
- `bun run check` is the macOS quality gate. Linux development hosts run the equivalent frontend checks plus Rust tests, formatting, and Clippy for `x86_64-unknown-linux-gnu`. Isolated-database migration smoke tests, arm64 packaging, keyboard checks, and VoiceOver smoke tests remain named macOS release checks.

## Compatibility Promises

v0.1.2 must preserve every v0.1.1 promise and add these for later releases:

- Instrument, Holding, Account cash, Instrument Quote, and FX Quote identities remain stable.
- Quotes are append-only observations with source and quote time; refresh does not rewrite history.
- Holding quantity in v0.1.2 is current state, not historical evidence of a trade.
- v0.1.3 may introduce Activity and quantity history but must not fabricate past trades from v0.1.2 edits.
- Native amount, native currency, base value, selected quote, and valuation completeness remain distinguishable.
- Provider-specific identifiers stay behind provider metadata and do not become Instrument identity.
- Manual valuation remains available without a provider account or network connection.
