# v0.1.6 Release Contract

## Purpose and Status

**Release theme:** Local Market Data — fetch replaceable external prices and FX rates without weakening Nestworth's local-first valuation model.

**Status:** `Implementation complete; release closeout pending`. Phases 0–5 are implemented and verified, and Phase 6 automated plus isolated-bootstrap evidence is recorded on the current development branch. The local arm64 `.app`/`.dmg` build succeeds at `src-tauri/target/aarch64-apple-darwin/release/bundle/`; see the [release evidence](v0.1.6-release-evidence.md) for exact validation and signing state. The [technical design](v0.1.6-technical-design.md), [implementation plan](v0.1.6-implementation-plan.md), and [compatibility baseline](v0.1.6-baseline.md) remain the implementation contract. Interactive isolated-data smoke, Developer ID signing/notarization, and publication evidence are not complete.

v0.1.6 activates the provider boundary prepared in v0.1.2. The first bundled provider is a temporary Yahoo Finance chart-endpoint adapter. It supplies current Instrument prices, current FX rates, and daily close history. The rest of Nestworth sees only normalized, persisted quote observations and never a Yahoo response.

## Release Goal

A user can bind a supported Instrument to a market-data symbol, select Provider as its quote source, fetch the latest value, and backfill the daily close data required by Nestworth history. The same explicit workflow can fetch the active Provider-selected FX pairs that valuation requires. Existing manual quotes remain complete, offline-capable, and authoritative whenever selected.

The central invariants are:

> Provider data is untrusted, user-initiated input that is normalized and persisted as an append-only quote observation before valuation may use it.

> A market-data provider is replaceable infrastructure. No Yahoo URL, JSON field, symbol convention, or floating-point value crosses into domain, valuation, history, or frontend code.

> A quote refresh never changes an Activity, Holding quantity, Account value, cost-basis declaration, ownership share, or quote preference without the user's separate explicit action.

## User Stories

- As an investor, I can enter a Yahoo-compatible symbol such as `NVDA`, `QQQ`, `^NDX`, or `BTC-USD` for an Instrument, choose Provider, and fetch its current price without re-entering a manual quote.
- As a multi-currency user, I can choose Provider for a required FX pair and fetch `USDCNY=X` or another normalized direct pair.
- As a user with history, I can request a bounded local-date range of daily close data, see what was fetched, reused from cache, skipped, or failed, and rebuild affected closed-day snapshots through the existing flow.
- As an offline or privacy-conscious user, I can continue to open, value, edit, back up, restore, import, and use manual quotes without any provider request.
- As a future contributor, I can add a provider adapter without changing Rust financial calculations, quote-table consumers, TypeScript financial calculations, or Yahoo-specific fixtures.

## Included

### Provider Capability

- A Rust-owned market-data provider registry with normalized latest-quote and daily-history operations for Instruments and FX.
- A production `yahoo_finance` adapter for the supplied HTTPS chart endpoint:
  - latest Instrument price from `regularMarketPrice`, falling back to the latest valid daily `close`;
  - latest FX rate from the same endpoint using `{FROM}{TO}=X`;
  - daily historical `close` values from aligned `timestamp` and `indicators.quote[0].close` arrays.
- Deterministic fake providers and recorded sanitized payload fixtures for all default tests. Default checks never depend on Yahoo availability.
- An explicit provider-capability DTO so the frontend can offer only supported workflows. Yahoo instrument search is not offered because the selected endpoint is a quote/history endpoint, not a symbol-search API.

### Current Quote Refresh

- Existing `refresh_instrument`, `refresh_required_fx`, and `refresh_all` commands become production-capable for Provider-selected eligible targets.
- Refresh only contacts an active, non-archived Instrument when its selected preference is Provider and its `(provider_key, provider_symbol)` resolves to a registered adapter.
- FX refresh contacts only normalized pairs currently required by active valuation and selected as Provider. It uses the bundled FX default provider, initially `yahoo_finance`.
- Each target reports success, cached/no-op, skipped, or a safe per-target failure. One target's failure never rolls back another target's persisted quote.
- A successful provider observation records `source_kind = provider` and `source_key = yahoo_finance`; it never silently changes Manual/Provider preference.

### Daily History and Local Cache

- User-initiated daily-close backfill for one eligible Instrument, required Provider FX pairs, or all eligible targets over an inclusive History-Origin-local date range.
- The range is bounded to 3,660 calendar days and must begin on or after History Origin and end no later than the last closed local date. A current refresh, not daily backfill, covers today.
- Daily history retains only the close value and the provider timestamp as existing Instrument or FX quote observations. Open, high, low, and volume are parsed nowhere and are not persisted in v0.1.6.
- A mutable local coverage cache records successful daily ranges, including market-closed dates. Subsequent non-forced requests fetch only uncovered subranges; an explicit force request may re-fetch a bounded range to accept provider revisions.
- Equal provider observations are not duplicated. A changed value at the same provider timestamp appends a later observation, preserving auditability and making the newer correction the deterministic selected quote.
- A provider quote whose timestamp can affect closed history marks the existing snapshot state dirty from that time. The existing bounded rebuild remains the only route that changes historical snapshot revisions.

### Product Experience

- Instrument create/edit exposes a Provider source only when a valid registered provider identity is selected. Yahoo binding is manual: provider `Yahoo Finance` plus a market symbol; no source search is implied.
- Instrument detail exposes latest quote provenance, refresh, and daily-history backfill. Provider and Manual selection remain explicit and visibly distinct.
- The existing required-FX experience exposes current refresh and daily-history backfill for eligible Provider pairs, with source, cached coverage, partial failure, and retry states.
- A Market Data action provides bulk current refresh and bounded historical backfill. It never runs on application startup, route mount, window focus, or a timer.
- English and Simplified Chinese strings, keyboard flow, non-color status labels, error recovery, and announced progress are required for every added workflow.
- Every Provider-facing surface (Instrument create/edit, Instrument detail, FX management, Market Data action) states in view that Yahoo is an unofficial, unaffiliated data source that may change format or become unavailable without notice, in both English and Simplified Chinese.

## Excluded

v0.1.6 does not implement:

- Background, scheduled, startup, focus-triggered, or closed-application refresh
- Provider-backed Benchmarks, benchmark backfill, price charts, OHLCV storage, intraday bars, corporate actions, dividends, splits, or adjusted-close accounting
- Broker, bank, wallet, exchange, trade, account-balance, or transaction synchronization
- Symbol search, security master data, automatic symbol guessing, ISIN resolution, or changing an Instrument's quote currency from a provider response
- User-supplied endpoints, API keys, OAuth, Keychain storage, plugins, remote configuration, or a user-selectable multi-provider routing policy
- Multi-hop FX, inferred cross-rates, synthetic prices, estimates for unsupported symbols, or use of a quote after a historical cutoff
- Rewriting, deleting, or converting manual quotes; automatic preference changes; automatic snapshot rebuild; or any Activity/ledger mutation
- A promise that Yahoo is an official, complete, real-time, licensed, or permanent data service

## Locked Product Decisions

| Decision | v0.1.6 contract |
| --- | --- |
| First provider | A bundled `yahoo_finance` adapter only; it is replaceable infrastructure, not a product dependency or guarantee. |
| Provider selection | One compiled-in provider registry. Instruments route through their existing `provider_key`; FX uses the bundled default. A multi-provider preference model is deferred. |
| Yahoo Instrument identity | User supplies a Yahoo symbol. It is URL-encoded by Rust and remains provider metadata, never a Nestworth identity. |
| Yahoo FX identity | Rust derives the direct request symbol as `{FROM}{TO}=X`; it does not accept a user-entered FX provider symbol. |
| Current quote fallback | Use `regularMarketPrice`; when absent, use the latest valid close in the returned daily series. Missing both is an unavailable/malformed provider result, never zero. |
| Daily value | Persist only a validated close. Daily bars retain Yahoo's timestamp; history selects them through the existing `quoted_at <= cutoff` rule. |
| Decimal boundary | Parse JSON numeric lexemes directly to `rust_decimal`-backed `UnitPrice` or `FxRate`; binary floating point is never used for a financial value. |
| Currency validation | The returned Instrument quote currency must equal the configured Instrument quote currency. FX must match the requested direct pair. A mismatch writes nothing. |
| Cache | Quote rows are append-only observations; daily coverage rows are mutable cache metadata. Backups retain both; canonical export continues to exclude provider cache data. |
| History invalidation | Each persisted provider quote calls the same dirty-range rule as a manual quote, using its provider timestamp. Refresh never rebuilds automatically. |
| Network authority | Rust only. Frontend receives DTOs and has no HTTP capability or relaxed CSP. |
| Rate limiting | At most two Yahoo requests run concurrently. HTTP 429 maps to `PROVIDER_RATE_LIMIT`; the current bulk operation stops issuing new Yahoo requests after that response and returns partial results. |
| Retries | No hidden automatic retry. The user may retry a failed current request or explicitly force a historical range. |
| Privacy | Startup sends nothing. Requests contain only the selected symbol or derived FX pair; logs, errors, and analytics contain no URL, symbol, raw payload, price, rate, or balance. |
| Data source disclaimer | Every Provider-facing surface states that Yahoo is an unofficial, unaffiliated data source that may change or become unavailable without notice; this is a visible UI requirement, not only a legal exclusion. |

## Acceptance Scenarios

### Current Instrument Quote

An active `NVDA` Instrument has `provider_key = yahoo_finance`, `provider_symbol = NVDA`, and Provider preference. Refresh calls the chart endpoint with the encoded symbol. If `regularMarketPrice` is a valid decimal in USD and `regularMarketTime` is valid, Nestworth appends a Provider quote with `source_key = yahoo_finance`. It changes neither the Instrument's currency nor quote preference. If the current field is missing, Nestworth uses the newest valid aligned close and its timestamp. If both are absent, it writes nothing and shows a safe failure.

### Direct FX Quote

An active Household valuation requires USD/CNY and its normalized pair preference is Provider. Refresh asks Yahoo for `USDCNY=X`, validates the returned direct rate, and appends a USD-to-CNY Provider FX quote. If Yahoo cannot supply the pair, the last valid local quote remains selectable and the result reports that pair as failed; all manual workflows remain available.

### Cached Daily History

The user backfills `QQQ` from 2026-01-01 through 2026-03-31. The adapter validates the chart arrays, persists every valid close in one target transaction, marks history dirty from the earliest inserted timestamp, and records successful daily coverage. Repeating the same non-forced request sends no provider request. A later force request that finds a corrected close appends a new observation at that timestamp instead of rewriting the earlier quote.

### Historical Safety

A backfilled daily FX quote falls before a previously completed snapshot cutoff. The quote is selectable only when its `quoted_at` is at or before that cutoff. The refresh records the earliest affected dirty date, but existing snapshot rows remain unchanged until the user runs the existing rebuild. A quote after a cutoff cannot alter that snapshot.

### Rate Limit and Offline Use

Bulk refresh succeeds for two targets, then Yahoo returns HTTP 429. Nestworth retains the two committed observations, reports the rate limit for the failing target, marks unstarted Yahoo targets as skipped due to rate limiting, and makes no automatic retry. Opening the app later makes no network request; Manual quote entry and valuation still work.

## Release Acceptance

v0.1.6 is complete only when:

- Migration `006` preserves all schema-`005` rows, selected current valuation, historical selection, snapshot revisions, lot replay, analytics goldens, manual quote behavior, backup/restore behavior, and future-schema zero-write protections.
- Yahoo response parsing is bounded, validates result cardinality, array alignment, timestamps, currencies, positive FX rates, finite canonical decimals, and all fallback rules without panics or raw-payload errors.
- Current and daily provider quotes use no binary floating point, preserve source provenance, deduplicate equal values, append revisions, and cannot change Manual/Provider preference.
- Daily coverage suppresses already-covered non-forced requests, handles an empty valid market-closed range, merges overlapping ranges deterministically even when two backfill requests for the same target run concurrently, and is changed only with a successful validated response.
- Every inserted provider quote marks the correct existing history dirty range; no provider quote after a cutoff is selected for that cutoff; provider refresh never rebuilds snapshots automatically.
- Instrument and FX eligibility, pair normalization, source routing, bounded concurrency, timeout, 429 stop behavior, malformed response, currency mismatch, unsupported symbol, network failure, and partial persistence are covered by deterministic tests.
- Default tests contain no live Yahoo request. The frontend has no HTTP plugin or expanded CSP/capability, and startup/mount/focus/timer paths do not call a provider.
- Generated bindings, command allowlist, locales, accessibility checks, frontend tests, migration tests, provider fixtures, historical/analytics goldens, `bun run check`, and isolated-data release checks pass.
- Every user-facing Provider workflow visibly discloses that Yahoo is an unofficial, unaffiliated data source in both required locales.

## Compatibility Promises

v0.1.6 preserves every prior promise and adds:

- Manual quotes remain fully supported and remain the only selected source unless the user explicitly selects Provider.
- Provider metadata and source keys are provenance, not financial identity. Changing or removing an adapter never reinterprets a stored quote.
- Every provider quote is append-only evidence. Mutable daily coverage is cache metadata and cannot affect valuation by itself.
- Current Overview, Portfolio, Account, history, gain, return, and attribution continue to read existing quote records through Rust selection rules; they do not make provider calls.
- Missing, stale, unsupported, delayed, malformed, or rate-limited provider data never becomes zero, one, an estimate, a fabricated quote, or a blocked local workflow.
