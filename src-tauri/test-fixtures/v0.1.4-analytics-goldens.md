# v0.1.4 Analytics Goldens

Synthetic expected values for v0.1.4 cost-basis, gain, currency-decomposition, return, and attribution tests. No real personal data. These numbers freeze the Phase 0 contract. Later phases must match them; they must not “fix” recorded v0.1.3 gaps.

The loadable schema-3 household is `src-tauri/test-fixtures/v0.1.3.sql`, built from the released v0.1.2 fixture plus posted Activities on migration `003`.

## Locked decisions

These are already locked in the release contract. Phase 0 records them so Phase 1+ cannot reopen them:

- FIFO is the only lot policy. There is no average-cost, LIFO, HIFO, or user lot selection.
- Lots are derived by deterministic replay of the posted ledger. They are not a persisted financial fact.
- A reversed Activity and its reversal are both excluded from lot replay. The audit rows remain in `activities`.
- Fees are never capitalized into cost basis. Gross and net gain are separate outputs.
- Daily TWR treats scope flows as available at the start of the local day they occur on.
- Benchmarks are deferred. No index series, peer comparison, or market-data provider is selected.

## Recorded v0.1.3 gaps

These are implementation facts encoded in `v0.1.3.sql`. v0.1.4 must respect them rather than invent missing columns.

- **Lot cost comes from persisted gross settlement, never a recomputed unit price.** FIFO buy 1 stores settlement `200` USD; buy 2 stores `480` USD. Cost is those amounts, not `quantity × unit_price` reconstructed later.
- **A confirmed zero-gross Buy persists no settlement leg.** Activity `01a0188f-8621-7a61-a206-bf5800173c36` has a holding leg only. Cost is zero and basis is known, distinct from unknown basis.
- **Trade fees have no `fee_kind`.** FIFO buy and sell fee legs have `role = 'fee'` and parent Activity `fee_kind` NULL. They must land in `tradeCommission` later, not be dropped.
- **Acquisition FX is not persisted** on trade legs. Historical at-or-before-cutoff selection is required. FIFO buy 1 is at `2026-01-04T02:00:00.000Z`; the eligible USD/CNY quote is `6.5`.
- **Origin QQQ quantity 3 remains unknown-basis.** Origin holding `30303030-3030-4303-8303-303030303030` is not consumed by FIFO sells. FIFO uses dedicated instrument VOO.

## Contract goldens (frozen)

These numbers are frozen in `docs/releases/v0.1.4.md`. Phase 1+ tests must reproduce them exactly.

### FIFO realized and unrealized gain

Dedicated VOO trades, not origin QQQ:

```text
Buy   2 × 100 USD  gross 200  fee 5
Buy   4 × 120 USD  gross 480  fee 6
Sell  4 × 150 USD  gross 600  fee 6
Consumed cost = 440 USD
Proceeds = 600 USD
Realized gain gross = 160 USD
Allocated fees = 14 USD
Realized gain net = 146 USD
Open lot remaining = 2 at cost 240 USD
Unrealized gross at 160 USD quote = 80 USD
```

Consumed cost is `200 + (480 × 2/4) = 440`. Allocated fees are `5 + (6 × 2/4) + 6 = 14`. Remaining lot cost is `480 × 2/4 = 240`. At `160` USD the open lot is worth `320`, so unrealized gross is `80`.

### Currency decomposition

Lot of 2, cost 200 USD (FIFO buy 1), `f0 = 6.5`, quote `150`, `f1 = 6.9`, Household base CNY:

```text
base cost 1300, base value 2070, base gain 770
instrument movement 650, currency movement 120
```

Identity: `770 = 650 + 120`. `f0` is the USD/CNY quote at or before `2026-01-04T02:00:00.000Z` (`6.5`). For the realized consumption, `f1` is the USD/CNY quote at or before the sell `2026-01-06T02:00:00.000Z` (`6.9`). Native value at `150` USD is `300`.

If no FX quote exists at or before acquisition time, this lot reports base gain only, decomposition status `unavailable`, and parent aggregates are incomplete. No most-recent-rate substitution.

### TWR

Synthetic contract series. It is not the current net worth of this household.

```text
Day 1 return 2%, Day 2 return 2%, TWR 4.04%
Naive 4.444% must never appear
```

Start-of-day flow assumption:

```text
Day 0 close   net worth = 100000
Day 1         deposit   =  10000
Day 1 close   net worth = 112200
Day 2 close   net worth = 114444
Day 1 return = (112200 − 100000 − 10000) / (100000 + 10000) = 2%
Day 2 return = (114444 − 112200) / 112200                    = 2%
TWR          = 1.02 × 1.02 − 1                                = 4.04%
```

A missing or incomplete snapshot day makes any period containing it unavailable and names the blocking local dates. The fixture’s incomplete `2026-01-03` and `2026-01-04` snapshots are the named blocking dates for periods that include those days.

## Query families

Analytics reads are Household-scoped and bounded. Phase 7 must keep these families and must not add a query inside a loop over lots, Activities, snapshot days, or snapshot items:

- History Origin header and baseline holdings
- Ordered Activity headers and legs for the analyzed Instruments and Accounts, loaded in one batch
- Cost-basis declarations for the analyzed lot identities, loaded in one batch
- Daily snapshot headers for the analyzed local date range
- Daily snapshot items for those headers, loaded in one batch
- Latest Instrument and FX Quotes for current unrealized value
- Historical FX Quotes at the acquisition times required by currency decomposition
- Snapshot dirty-range state

Per-lot queries and per-day queries are prohibited. The FIFO replay and every return calculation run in memory over one consistent read snapshot.
