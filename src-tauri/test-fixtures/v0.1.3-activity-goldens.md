## Timezone Fixtures

Timezone is not a schema `002` column. Phase 1–2 tests must use:

### DST-capable History Origin

- IANA timezone: `America/New_York`
- Spring-forward nonexistent local time: `2026-03-08 02:30` (clocks skip `02:00`–`03:00`). Reject with `INVALID_ACTIVITY_TIME`.
- Fall-back ambiguous local time: `2026-11-01 01:30` (the hour `01:00`–`02:00` occurs twice). Require an explicit earlier/later offset choice; do not guess.

### UTC fallback

- Unresolved host timezone records `UTC` with `timezone_confirmed=false`.
- Current reads remain available.
- Activity and snapshot writes return `HISTORY_TIMEZONE_CONFIRMATION_REQUIRED` until the user confirms UTC or another valid IANA timezone.
- Confirmation is allowed only before the first Activity or persisted snapshot, then the timezone is immutable in v0.1.3.

## Trade and Fee

A Holdings Account contains `1000` USD cash and no QQQ. Post a Buy of `2` QQQ × `100` USD with a `5` USD fee:

```text
Settlement cash = 795 USD
QQQ Quantity = 2
Trade principal = 200 USD
Fee = 5 USD
External flow = 0
```

At an exact `100` USD QQQ quote, Account value is `995` USD. The `5` USD difference is the explicit Fee.

## Cross-Currency Transfer

Transfer `100` USD to `690` CNY. Rust derives `1 USD = 6.9 CNY` from the two native amounts.

```text
Source native = 100 USD
Destination native = 690 CNY
FxRate = 6.9
Classification = internal
External flow = 0
```

Transfer `1000` CNY to `186.9` SGD with Household base CNY and market quote `1 SGD = 5.3 CNY` at effective time:

```text
Source native = 1000 CNY
Destination native = 186.9 SGD
Transaction FX = 0.1869
Inverse display = 5.350454788657
Destination in base = 990.57 CNY
Conversion spread = 9.43 CNY loss
External flow = 0
```

Both native amounts and the derived rate are retained. Conversion spread is a computed overlay. Later snapshot movement from market FX is not reclassified as a deposit or withdrawal.
